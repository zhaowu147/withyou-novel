# 架构与容错优化说明

日期：2026-07-30
基线：当前磁盘代码，不使用 Git 历史推断项目事实。

## 全局架构判断

WithYou 是 Next.js 16 + React 19 + Electron 的本地优先小说工作台。浏览器状态负责交互，小说目录与本地 JSON 是持久化事实源；工作区租约绑定会话与小说；服务端 Agent 通过只读工具读取文件树，写入仍经过显式流程。

本轮没有引入另一套并行状态系统，而是在现有边界中增加统一语义契约、共享流解析和持久化保护。

## 已实施优化

### 1. 语义契约成为正式执行门禁

此前用户输入可以直接进入生成；理解错误只能在结果出来后发现。现在生成、Writer、工具精修和 Agent 工作台必须绑定已确认契约。

保护包括：

- 项目/工作区隔离；
- 版本乐观并发；
- 不可变锁定快照；
- 内容哈希；
- 来源文件过期检测；
- 项目事实冲突阻断；
- 跨进程执行领取锁；
- 同一版本重复或并发执行拒绝；
- 执行失败与验证失败状态落盘。

### 2. SSE 消费统一并具有有界失败

ChatPanel 原有两份近似的手写 SSE 循环，容易在分块边界、旧请求覆盖新请求和永不返回的连接上出现差异。

新增 `src/lib/ai/sse-client.ts`，统一处理：

- 跨网络分块的事件拼接；
- 畸形 JSON 事件隔离；
- AbortSignal；
- 请求代际检查，旧流不会覆盖新会话；
- 无数据超时；
- 结束、异常和取消时释放 reader 与计时器。

两个聊天生成入口改为同一个消费者。

### 3. 提示词包持久化加固

`prompt-store.ts` 现在：

- 校验小说目录和提示词包 ID；
- 拒绝路径穿越；
- 使用原子 JSON 写入和备份；
- 主文件损坏时从备份恢复并保留损坏副本；
- 激活状态读取时规范化数据。

自定义提示词不再依赖一次直接覆盖写入。

### 4. AI 表单填写收敛为单轮协议

旧流程按字段多次请求并重复读取资料。新流程：

1. 服务端只读取一次项目上下文；
2. 一次模型调用返回完整字段对象；
3. 解析器仅接受当前 schema 的键；
4. 已有值不覆盖；
5. `select` 值必须属于模板选项；
6. 非法 JSON 不进行猜测性降级。

旧单字段 API 明确返回 `410 AI_FILL_DEPRECATED`，避免双轨长期并存。

### 5. 生成提示和结构化协议统一

角色生成不再走绕过提示词包、语义契约和结构校验的特殊分支。所有文本创作工具共享：

- 服务端事实读取；
- 激活提示词编译；
- 语义契约注入；
- 结构化输出校验；
- 只修协议、不重写创作内容的 JSON 修复。

### 6. 设置与本地数据迁移

设置版本升级为 v3，增加低风险任务自动确认开关。旧设置读取时使用默认值补齐，不要求用户手工迁移，也不覆盖 API Key 等既有本地配置。

### 7. 本地来源校验兼容代理别名

本地代理可能把请求 URL 写成 `localhost`，而浏览器 Origin 保留 `127.0.0.1`。来源防线现在只在协议和端口一致、两端都明确为 loopback 时允许这组别名；外部域名、不同端口、非 loopback Host 和代理转发仍然拒绝，避免为兼容性牺牲 CSRF 防线。
