# Writer Agent — 执行流程 (from story-long-write)

> 本文件为精简执行版

---

## 核心方法

1. **先定情绪，再定故事**。每个场景都必须服务于明确的情绪目标。
2. **从验证过的模式出发**。用模块组装，不要重新发明。
3. **只加载必需信息**。写每章时只加载"不知道就会写错"的信息。

---

## 单章写作 10 步

### 1. 检查细纲
读 `大纲/细纲_第{N}章.md`。不存在 → 必须先补建细纲。

### 2. 读取上下文
- 上一章正文
- 本章细纲（含钩子设计）
- 待回收伏笔
- 本章涉及的角色/势力设定
- 角色当前状态快照（如有）
- 对标参考（如有）

### 3. 写前准备
- **状态筛选**: 从角色状态中筛本章涉及角色，从伏笔中筛待回收/推进
- **模块召回**: 目标情绪词 → 借鉴哪个技法 → 用在哪个段落。答不出先回读
- **指令确认**: 一句话写清本章意图。「快节奏打脸——账单暴露→逼问→反证→公开代价」

### 4. 写作
- 第1章避免内心戏/独白开场，必须外化为可见事件
- 正文不得出现「第X章/上一章/本章/前文/伏笔/细纲/读者」等工程词
- **细纲优先边界**: 只展开本章细纲已有事件，不自造新主线/新角色/新反转

### 5. 字数验证
- 写完立即统计字数（Python 字符统计）
- < 目标90%: 对照情节点预算找欠账，补密点展开
- > 目标×1.1: 压过场、合并疏点
- 默认最低3000字/章

### 6. 质量自检
- 章尾是否有往下看的理由
- 爽点出手前是否有可指认的危机/期待铺垫
- 装逼/打脸/揭露章在场配角是否有差异化反应

### 7. 元信息扫描
检查正文是否有工程词泄漏，有则改写为场景内表达。

### 8. 禁用词扫描
对照 banned-words.md，一级词命中即替换。

### 9. 更新追踪
- 更新伏笔状态（新增/回收）
- 更新时间线
- 更新角色状态（身份/能力/关系/公众形象变化）
- 新角色/势力自动建档

### 10. 中途快照（每3章）
- 更新进度到追踪/上下文.md
- 确认最近3章文件已落盘且>100 bytes

## 字数硬约束

| 节奏 | 最低字数 |
|------|----------|
| 高速推进 | ≥2000字/章 |
| 正常节奏 | ≥3000字/章 |
| 舒缓铺垫 | ≥3000字/章 |
| 高潮爆发 | ≥2000字/章 |

**默认最低: 3000字/章。不达标必须补足。**

---

## 写作技巧速查

| 场景 | 技巧 |
|------|------|
| 开篇500字 | 必须有钩子，不从天气/风景开始 |
| 对话 | 推进剧情或揭示性格，不为凑字 |
| 打斗 | 写策略和反转，不写「你一拳我一脚」 |
| 日常 | 有人物互动和伏笔，不只「吃饭睡觉」 |
| 任务卡点 | 卡出信息/关系/代价/选择/伏笔变化；删掉无损就删 |
| 爽点释放 | 铺垫充分、释放干脆 |
| 爽点密度 | 高压章每3000-5000字一个爽点 |
| 章尾 | 每章结尾让读者想翻下一页 |
| 情绪验证 | 写完回头检查：读者感到什么？没感到就补 |
