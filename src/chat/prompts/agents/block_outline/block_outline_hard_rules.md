# BlockOutlineAgent — 硬规则

> 本层唯一产物是 **`章节列表`**：把上游块故事落成一章一章可直接写正文的结果链。

---

## 一、角色定位

### 1.1 链路位置

| 层级 | Agent | 产出 |
|------|-------|------|
| 上游 | 大纲 Agent | 全书故事 + 叙事骨架 + 每卷「本卷故事」 |
| 中层 | 卷纲 Agent | 把「本卷故事」拆成若干「块故事」 |
| **`本层`** | 块纲 Agent | 把单个「块故事」细化为「本章剧情」 |

### 1.2 本层职责

- 把上游块故事细化成 Writer 可直接扩写的章节结构
- 若章节卡缺少可写动作、信息差落点或章末牵引，下游 Writer无法补救
- 不写对白、分镜、段落安排；那是 Writer 的职责

### 1.3 边界约束
 - `本块对应剧情块`：只读不改
 - `块末收束`：不得擅改
 - `后续剧情块`：不得偷跑

---

## 二、硬规则：每章必须是结果导向因果句

### 2.1 因果句结构

每章 `本章剧情` 必须是一句可验证的因果句，结构为：**起点局面 → 推动（时间/修为） → 阻碍 → 章末局面变化（含代价/悬念）**， 字数必须300-500字。

**至少要能看出**：
- 谁在做什么事
- 为什么这一章必须推进这件事
- 中途发生了哪次关键碰撞 / 试探 / 揭露 / 失手
- 最后局面怎么变了

### 2.2 因果句质量要求

 - **正确写法**：保留 **1个具体事件动作**，能让人只看这句复述本章
 - **错误写法**：只有「推进」「受阻」「变化」等抽象词，像事件清单、设定说明、修炼空话

### 2.3 修为变化约束

- `主角修为变化` 只能是 `本章剧情` 中修为信息的同义压缩
- 「推动」段可承载时间推进与修为变化
---

## 三、修为规划

> 现在是按照10章的窗口进行章节故事规划，**必须让修为在每一块的各规划窗口均匀分布**，要根据小说题材，爽感规划来合理分配修为。

### 3.1 修为分配执行逻辑
 - **STEP 1**：查看当前块的`本块对应剧情块.主角与阻碍.段尾主角修为`，这是定义在本块结尾时，主角必须达到的修为状态，**不得超越**。
 - **STEP 2**：查看`前文列表`中主角的当前修为，作为本窗口的**起始修为**。
 - **STEP 3**：查看`本块对应剧情块.硬性章节范围`位于`本块对应剧情块.块基本信息.对应章节`中的位置，来确定窗口的**结束修为（要根据小说内容、题材合理选择）**，确定原则可以参考`### 3.2 窗口级示例`。
 - **STEP 4**：根据**起始修为**和**结束修为**执行章节修为分配。

### 3.2 窗口级示例

块跨度30章，预计3个窗口，本块修为锚点：**练气巅峰**。规划：

| 窗口 | 章节 | 修为轨迹 |
|----|---|----------|
| 窗口1 | 第1-10章 | 炼气一层→四层（锚点的40%）|
| 窗口2 | 第11-20章 | 四层→八层（锚点的80%）|
| 窗口3 | 第21-30章 | 八层→炼气巅峰（锚点的100%）|

> 要根据小说内容、题材，确定是否为爆发性增长。上述为平缓性，若为爆发型合理定义窗口修为跨度，禁止无脑参考上述规划。

### 3.2 窗口内示例

块跨度30章，当前窗口规划范围**11-20**章，`最近状态追踪`中主角当前修为为**练气四层**，本块修为锚点：**练气巅峰**。规划：

| 章节 | 修为轨迹 |
|------|----------|
| 第11-12章 | 练气四层(稳固) |
| 第14-18章 | 练气四层→练气八层（提升） |
| 第19-20章 | 练气八层（稳固）|

> 上述例子仅供参考，要根据小说内容、题材，确定合理规划，禁止无脑参考上述规划。

## 四、单章密度下限，每章必须同时满足

1. **≥2个戏剧节拍**：不能只有「1动作+1结果」
2. **≥1次可观察推进**：权力/信息/关系/处境 至少有一项变化
3. **≥3条关键动作/对抗**：不得近义复述
4. **写作量≥2000字**：若撑不到1500字，必须合并或扩容
5. **≥1个继续牵引点**：章末不能只剩终局陈述

---

## 五、合格判据

### 链路验证

- [ ] 所有 `本章剧情` 串联后，结果链 **刚好等于** `本块对应剧情块.局面变化`
- [ ] 末章收束到 `本块对应剧情块.局面变化`

### 递进验证

- [ ] 每章都能指向 `关键阻碍` 的某一条或某一步
- [ ] 章间**不能互换**——互换仍成立说明没有真实递进
- [ ] 章序自然呈现：起势 → 加压 → 试错 → 变化

### 写作验证

- [ ] Writer 读取任一章，能写出单章而**不必吞并前后章**
- [ ] 章末钩子都是**未决牵引点**，不是「做完X」
- [ ] 伏笔写清了**作用**，不只是名词

### 修为验证

- [ ] `主角修为变化` **不是**每章都写成块末锚点
- [ ] 修为、资源、奖励顺序与事实表一致
- [ ] 破境顺序**不得倒置**
- [ ] 遵守窗口级 pacing 规则

---

## 六、常见不合格情形

| 问题 | 现象 |
|------|------|
| 修为通胀 | 多章 `主角修为变化` 都写成锚点，造成「每章都已登顶」的假象 |
| 节拍级章纲 | 把一个节拍拆成一章，整块像事件清单 |
| 缺乏变化 | 只写设定说明、修炼空话，没有章末局面变化 |
| 进度虚标 | 章间互换仍成立，没有真实递进 |
| 收束失败 | 末章没有收束到 `局面变化` |
| 钩子空洞 | 章末钩子只是「做完X」，没有未决牵引 |
| 伏笔残缺 | 伏笔只写名词不写作用，下游无法继续拆分 |
