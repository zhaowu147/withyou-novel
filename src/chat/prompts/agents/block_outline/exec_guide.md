# BlockOutlineAgent — 执行逻辑

---

## 一、输入契约

### 1.1 核心输入（按优先级）

| 优先级 | 字段 | 作用 |
|--------|------|------|
| 1 | `本块对应剧情块` | 含块故事/对应章节/本块主角目标/关键阻碍/失败后果/主角修为锚点/局面变化等。所有章节都必须是它的细化展开 |
| 2 | `硬性章节范围` / `必须输出章数`  | 章数、章号、区间的硬约束 |
| 3 | `本卷基本信息`  | 用于对齐本卷故事/主角等级变化/卷末期待位 |
| 4 | `大纲` | 用于吸收世界背景、力量体系、核心人物等必要约束 |
| 5 | `前文列表` | 锚点章之前的章节列表摘要（承接节拍/修为阶梯/悬念） |

### 1.2 边界约束

| 字段 | 作用 |
|------|------|
| `活跃实体摘要` / `冷却实体摘要` | 块内可调用角色、地点、势力、物件的边界 |
| `未回收伏笔` | 选择1-3条在本块内推进；同一条线只做「埋下/激活/回收」中符合阶段的一种 |

---

## 二、生成步骤

1. **Step 1** 读前文列表，确认进块起点与首章章号、章末钩子与修为承接。
2. **Step 2** 读本块对应剧情块全字段，只内化不复写，锁定本块终点。
3. **Step 3** 生成初版章节列表：每章补齐因果句、冲突焦点、情节模式、关键动作、钩子。
4. **Step 4** 做单章密度体检，标记所有薄章。
5. **Step 5** 做相邻合并扫描，必要时扩容戏剧量，迭代到收敛。
6. **Step 6** 章号重编并兑现硬性章节范围 / 必须输出章数。
7. **Step 7** 校验末章收束、修为时间轴、情节模式分布、伏笔阶段。

---

## 三、上游信息内化

> 读取 `本块对应剧情块` 时，至少内化四件事（仅用于规划，不写入输出）

| 需内化 | 说明 |
|--------|------|
| 块故事 | 本块最终要把局面推到哪里 |
| 本块主角目标 | 主角在本块里必须得到/守住什么 |
| 关键阻碍 | 各章要撬动的核心阻力是什么 |
| 局面变化 | 末章必须收束到什么状态 |

**原则**：每章都是 `关键阻碍` 被撬动的一小步。章间递进应体现：**阻碍 → 试错 → 部分推进 → 新阻碍暴露**。

## 四、情节模式选型

### 4.1 九种模式

| 模式 | 适用场景 |
|------|----------|
| `冲突对抗` | 主角与明确反派正面对决 |
| `竞争排名` | 多人争夺同一高诱惑奖励 |
| `身份职业` | 基于身份/职业展开任务或差事 |
| `建设养成` | 主角创立事业/势力/装备 |
| `情感关系` | 围绕情感需求产生矛盾与推进 |
| `悬疑解密` | 沿线索探索并逐步揭露真相 |
| `博弈策略` | 计谋、试探、陷害、反制 |
| `冒险奇遇` | 超常规场景中的未知探索 |
| `生存副本` | 强制规则下的生死游戏 |

### 4.2 选型约束

| 上游 `主钩子类型` | 优先选 | 禁选 |
|-------------------|--------|------|
| 被迫压力钩 / 人前显圣钩 | 冲突对抗 / 生存副本 | 情感关系 |
| 排行贪欲钩 / 人前显圣钩 | 竞争排名 / 冲突对抗 | 悬疑解密 |
| 人物情感钩 | 情感关系 / 冲突对抗 | 博弈策略 |
| 未知悬疑钩 / 方法掌控钩 | 悬疑解密 / 博弈策略 | 冲突对抗 |
| 信息前置钩 | 博弈策略 / 冒险奇遇 | — |
| 外挂神器钩 / 解决能力钩 | 冲突对抗 / 建设养成 | — |

### 4.3 分布约束

- 本块章数 ≥ 5 时，单一 `情节模式` 占比**不得超过60%**

### 4.4 信息差落地要求

| 信息差策略 | 落地要求 |
|------------|----------|
| 爽感预期 | 至少1条动作体现「主角有底牌/方法，但阻碍先被加码」 |
| 预期前置 | 至少1条动作体现「读者先知风险/惊喜，而主角尚未完全知晓」 |
| 方法预期 | 至少1条动作体现「敌方/对手预铺局」或「主角反制预铺局」 |
| 悬疑未知 | 至少1条动作体现「异常线索暴露 / 真相被撬开一角」 |
| 无 | 不强行设计信息差，但章末必须有未决牵引 |

信息差不允许太过于简单，也不允许设下相邻章节信息差，信息差必须有章节跨度。

### 4.5 情节模式最低动作要求

| 情节模式 | 最低动作要求 |
|----------|--------------|
| `博弈策略` | 至少1条试探/误导/反制动作 |
| `情感关系` | 至少1条关系位置变化动作（逼近、疏离、护短、误伤、让步） |
| `悬疑解密` | 至少1条异常线索暴露动作 |
| `竞争排名` / `冲突对抗` | 至少1条显性压制或反压制动作 |

## 五、密度体检与合并

### 5.1 单章密度体检

逐章检查以下项，任一不满足标记为 `DENSITY_LOW`：

- [ ] ≥2个戏剧节拍
- [ ] `关键动作/对抗` ≥3条且无近义复述
- [ ] ≥1次权力/信息/关系/处境 的可观察推进
- [ ] 信息差策略（若不为`无`）已落到至少1条可写动作或钩子
- [ ] 估算写作量能自然撑到2000-5000字

### 5.2 相邻合并扫描

从第1章开始两两扫描：若两章合并后能写成一句合理因果句，且信息量估算不超过3500字，**必须合并**。

**合并规则**：

| 字段 | 合并后取值 |
|------|------------|
| `关键动作/对抗` | 合并 |
| `伏笔操作` | 合并 |
| `本章剧情` | 重写新的因果句 |
| `主角修为变化` | 只保留合并后本章内**真实发生的档位结论** |
| `章末钩子` | 取更后的那一条 |

### 5.3 迭代收敛

重复「密度体检 → 相邻合并扫描」，直到：

- [ ] 无可继续合并的相邻对
- [ ] 无 `DENSITY_LOW`

### 5.4 章数合理区间

| 校验 | 说明 |
|------|------|
| 多于上限 | 说明仍是节拍级章纲，继续合并 |
| 少于下限 | 说明戏剧量不足，优先扩容阻碍/反转/代价 |

建议区间：`对应章节段长 × 0.3-0.5` 倍

## 六、收束与一致性

### 6.1 章号重编

- 若合并后出现章号洞，按最终章数连续重编
- 完整覆盖 `硬性章节范围`

### 6.2 末章收束

- 串联所有 `本章剧情` 的局面变化
- 确认末章**正好收束**到 `本块对应剧情块.局面变化`
- 若是过渡性收束，末章因果句必须显式写明「余波下次续接」

### 6.3 时间推进

- 显式时间跳跃必须写入 `本章剧情`
- 同步交代与跨度匹配的修为/处境/事件变化
- 破境章必须写清**代价**

### 6.4 配角/势力动作

- 要么写进 `关键动作/对抗`
- 要么体现在 `登场角色`

### 6.5 资源与境界时间轴

**禁止出现**：

| 禁止项 | 示例 |
|--------|------|
| 修为变化千篇一律写成锚点 | 多章都是「→炼气巅峰」 |
| 破境顺序倒置 | 先到筑基又无解释地回到炼气 |
| 资源时序颠倒 | 先拿到某境界入口资源，再到达该境界 |

### 6.6 伏笔操作约束

- 同一条伏笔线在同一章内只做**一种操作**：`埋下` / `激活` / `回收`
- 多章重复同一戏剧功能时，每次必须有**升级点**

## 七、输出规范

本层唯一输出 **`章节列表`**，不输出任何块级字段。每章必须生成以下字段。

### 7.1 核心字段与填写要求

| 字段 | 要求 |
|------|------|
| `本章剧情` | 按因果句写，含时间推进、必要修为变化、代价/悬念；保留清晰事件经过，让人只看这句也能大致知道本章发生了什么（1-2个关键事件） |
| `主角修为变化` | 对本章剧情中修为信息的**同义压缩**，修为必须承接上一章，体现的是当前章节主角的修为状态变化 |
| `本章冲突焦点` | 明确本章撬动 `关键阻碍` 的哪一条或哪一步 |
| `情节模式` | 九选一，按第四章规则选择 |
| `关键动作/对抗` | 至少3条，不得近义复述；至少1条推进主干的硬动作 + 1条放大体感/关系/压迫/信息差的信息动作 |
| `登场角色` | 本章承担戏剧作用的关键角色；纯过渡可`[]` |
| `伏笔操作` | 无则`[]` |
| `章末钩子` | 下一章的未决牵引点，且要与本章信息差兑现方式匹配 |


### 7.2 输出结构

> 严格JSON，不附加任何说明。

```json
{
  "章节列表": [
    {
      "章节号": "第X章",
      "本章剧情": "起点局面→推动(含时间/修为)→阻碍→章末局面变化(代价/悬念)（约300字）",
      "主角修为变化": "境界A→境界B（仅本章内真实发生），无变化则写境界A",
      "本章冲突焦点": "本章撬动关键阻碍的哪一步，1句",
      "情节模式": "冲突对抗 | 竞争排名 | 身份职业 | 建设养成 | 情感关系 | 悬疑解密 | 博弈策略 | 冒险奇遇 | 生存副本",
      "关键动作/对抗": ["动作或对抗点1", "动作或对抗点2", "动作或对抗点3"],
      "登场角色": ["本章关键出场角色；纯过渡可[]"],
      "伏笔操作": [
        {
          "操作": "埋下|激活|回收",
          "伏笔": "完整句，与账本或新埋一致",
          "附注": "埋下填触发条件；回收填兑现说明；激活填空字符串"
        }
      ],
      "章末钩子": "下一章读者必须想点开的未决点"
    }
  ]
}
```

## 八、自检清单

### 8.1 章节链路

- [ ] 所有章局面变化串联后，是否**刚好等于** `本块对应剧情块.局面变化`
- [ ] 每章 `本章冲突焦点` 是否都能指向 `关键阻碍` 的某一条或某一步
- [ ] 相邻章是否存在真实递进，而非互换或复读
- [ ] 每章 `章末钩子` 是否都是**未决点**而非「做完X」

### 8.2 因果句形态

- [ ] `本章剧情` 是否具备完整结构，而非关键词堆砌/设定说明/过程流水账
- [ ] 只看 `本章剧情`，不看 `关键动作/对抗`，是否仍能大致知道本章发生了什么
- [ ] 是否包含至少1个**具体事件动作**，而非只有抽象推进词
- [ ] 含时间跳跃的章，是否同步交代了跨度匹配的修为/处境/事件变化
- [ ] 破境章/密涨章是否写清了**代价**

### 8.3 单章密度

- [ ] 每章是否≥2个戏剧节拍
- [ ] `关键动作/对抗` 是否≥3条且**无近义复述**
- [ ] 每章是否至少1次可观察推进
- [ ] 纯独角戏章是否全块≤1章且**不连续**
- [ ] 是否已经执行合并扫描并**迭代到收敛**
- [ ] 最终章数是否符合经验区间或工程硬约束

### 8.4 结构约束

- [ ] 章数与章号是否严格匹配、连续、**无缺漏**
- [ ] 若有 `必须输出章数` / `硬性章节范围`，是否严格满足
- [ ] 首章章号是否等于 `前文列表` 中最后一项「章节号」+1

### 8.5 修为 / 伏笔

- [ ] 除破境/暴涨章外，是否多数章为`无`或`巩固`
- [ ] `主角修为变化` 是否只是**本章**剧情的同义压缩（无提前透支未发生破境）
- [ ] 是否遵守**窗口级pacing**（若本块跨多窗口）
- [ ] `伏笔操作` 是否来自 `未回收伏笔` 或有**合理新埋理由**
